## 本研究 FS 設定確認

實驗二只有 MI、CART、RFE、SHAP 排序四種方法，各保留 50%／80%，即 9／14 特徵。不是參考論文的 MI／GA／CART 組合，也沒有做 Filter → Wrapper → Embedded 串接。通用設定中另有 mRMR、LASSO、RFECV 等名稱，但固定年份正式入口並未讀取它們，不將其寫成本研究已完成的方法。

- MI：`mutual_info_classif`，連續密集輸入，預設 `n_neighbors=3`，依本次種子設定 random_state，分數平手使用原欄位順序。
- CART：`DecisionTreeClassifier`，balanced 權重，gini、best，深度不限、min_samples_split=2、min_samples_leaf=1，未另剪枝或抽取候選欄位。
- RFE：使用上述決策樹，step=1，達 9／14 特徵停止；輸出維持原欄位順序。
- SHAP：LightGBM 100 棵樹、balanced，主要預設 learning_rate=0.1、num_leaves=31、max_depth=-1，四執行緒；只在 Old-fit 計算精確樹貢獻，去除 bias 後按平均絕對值排序，平手使用原欄位順序。
- 六個 XGBoost 基礎模型並不因此採 balanced 類別權重。FS 的權重設定與後續分類器分開，分區、前處理、FS、採樣、訓練的順序維持原設定。

## 最新研究方法核對的依據與界線

正式固定年份 run 為 `results/phase2_ensemble/standard_dynamic/runs/20261004T202331745995Z/`，目前只有此一正式 run 目錄。核對資料 SHA-256 與原 manifest 相同。現行入口曾抽出共用函式，因此整份程式 hash 與當時不同；已從保存的原文快照核對原 run 的來源雜湊，再以 AST 比較八個主要函式：load_data、partition_data、fit_representation、select_threshold、static_candidates、evaluate_predictions、make_model、feature_columns，內容均一致。採樣器、XGBoost wrapper、DESlib 相容層、評估函式與模型／採樣設定亦與正式 run 保存雜湊一致。

這能支持「目前固定年份集成與 FS 的方法說明與已完成實驗一致」，不能支持「整份論文的所有研究與證據均已完成」。第一實驗的分類器選型銜接、同協定 Retrain，以及公司數／標籤版本差異仍列為缺口。滑動視窗事件 target 與加權擴充是別的協定，沒有混入這兩項實驗。

來源驗證由 `scripts/thesis/method_reference_inventory.py` 執行，證據存於 `method_reference_revision_20261027/inventory.json`；年度計數與 FS 入選頻率可由同一入口重建。`config/thesis_sources.json` 固定此核對清單雜湊，一般同步檢查亦核對其上游來源與生成表。統計數值的來源仍為上一輪固定的 bootstrap 分析，不因文字修訂重算或換成其他檢定。

## 寫法調整

開頭改為直接說明歷史與近期資料的取捨，再交代實際怎麼比較；刪減重複的「為確保」「不預設」「以維持一致性」與多次相同的限制宣告。需要保留的限制集中在選型說明、資料來源差異與附錄，不為了句子順暢而省略。表格區分研究實際指定值與套件預設值，避免「已有超參數表」卻無法判斷哪個設定真的跑過。
