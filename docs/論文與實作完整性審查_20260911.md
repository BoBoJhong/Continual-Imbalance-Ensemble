## 1. 方法實際如何運作

### 1.1 B 路線

實作：[rolling_bankruptcy_overlap_ensemble.py](../experiments/phase_flexible/rolling_bankruptcy_overlap_ensemble.py)、[study3b_continual_runtime.py](../experiments/phase_flexible/study3b_continual_runtime.py)。

對 Test 特徵年 t，最新訓練特徵年是 t−2，validation 是 t−1，test 是 t；衍生目標把特徵年對應到下一年度事件。這個時間契約仍依賴標籤成熟假設。

- 主分類器：XGBoost；B 使用 X1–X18，沒有 FS。
- 每個新模型在自己的三年資料上從頭訓練；imputer、scaler 各自只 fit 該訓練窗口，Tomek 只處理訓練列。
- 保留三個模型，分別以 t−4、t−3、t−2 為窗口終點。三個三年窗口聯集是五年，不是三年。
- 舊模型凍結；每年新增一個、FIFO 淘汰一個；機率等權平均。沒有 Old/New 權重搜尋。
- 沒有梯度式 replay buffer，但新窗口會再次讀取重疊歷史原始資料；不能稱完全不需要歷史資料。
- F1 門檻及 FPR-budget 門檻在 validation 選，再固定套用 test。它是年度 batch 更新，不是逐筆即時學習，也不是由漂移警報觸發更新。

### 1.2 A 不能只用一個名稱概括

既有 A 的 ROSS／DAWCE／AdaptiveChoice 包含邊界、取樣模型池或權重選擇；新公平比較中的 `A_validation_boundary_equal` 則只用事件目標、兩個 Tomek XGBoost、validation 選切點、固定等權。

後者可稱 **A-inspired validation-boundary baseline**，但不是完整 DAWCE 的等價移植。舊 Study 使用公司最終狀態標籤的結果，不能與 B 的事件目標分數直接合併排名。

## 2. 本輪獨立驗證結果

### 2.1 數值可重算，但不能只看 AUC

從 [fair_predictions.csv](../results/phase_flexible/study3_ab_fair/runs/20260909T122839561377Z/seed_42/fair_predictions.csv) 重新用 sklearn 計算；各方法均為 33,636 列、289 正例，方法內的 seed／年度／來源列／公司組合鍵沒有重複。

| 方法 | Pooled AP | Pooled ROC-AUC | 年度 AP 等權平均 |
|---|---:|---:|---:|
| B-model FIFO3 | 0.121487 | 0.857592 | 0.141785 |
| B-data | 0.120160 | 0.852869 | 0.138136 |
| A-inspired boundary | 0.105639 | 0.842192 | 0.134335 |
| Recent3y | 0.096580 | 0.845030 | 0.121867 |
| Recent5y | 0.104993 | 0.835629 | 0.128362 |
| FullHistory | 0.057225 | 0.815447 | 0.074308 |

這些是描述性點估計，不表示每一對差異都顯著。Pooled AP 混合不同年度模型的分數，年度 AP 平均則描述逐年度排序；兩者回答不同問題，應並列而非互換。

B-model 的實際辨識與警報負擔：

| Validation 選門檻方式 | TP | FP | FN | TN | Recall | Precision | Test FPR | 警報數 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| F1 grid | 62 | 296 | 227 | 33,051 | 21.45% | 17.32% | 0.89% | 358 |
| FPR ≤ 5% 下最大 Recall | 116 | 1,405 | 173 | 31,942 | 40.14% | 7.63% | 4.21% | 1,521 |

因此，較高 AUC 不能改寫成「已能有效抓出大部分破產公司」。第二種門檻漏掉約六成正例，且警報中約九成為誤報；是否實用取決於人工審查成本與漏報代價，目前尚未定義。

逐年核對：每年正例只有 21–36 個；B 年度 AP 約 0.0346–0.2796。採 validation FPR-budget 門檻時，2012、2015、2018 的 test FPR 分別為 5.84%、5.99%、5.02%。這不是 test 洩漏，而是年度分布變動下 validation 限制不保證外推。

## Critical Issues

優先度：P0 為可使核心研究主張失效；P1 為影響論文可信度與主要比較；P2 為邊界實作／重現性問題。以下明確區分目前已發生的論述問題與未證明污染現有結果的程式風險。

### R1：事件與資訊可用時間仍未被真正觀測

- **Priority：P0（若主張前瞻有效）；現階段回溯研究的重要適用限制。**
- **File／Function：** `rolling_bankruptcy_overlap_ensemble.py::build_event_target`；`study3b_continual_runtime.py::prepare_label_ledger`；論文 §3.1.1。
- **Problem：** 由 failed 公司最後觀測年推定事件，並設定 `label_available_year = event_year`。年份存在，不代表財報與事件在當時已公開。原論文公司數 8,262 與本地 8,971 的來源差異亦尚待解釋。
- **Why it matters：** 對不曾發生事件、退出樣本或資料尾端的公司，可能涉及追蹤不足／右設限；2018 特徵對應 2019 事件也需要結果追蹤證據。現有程式可隔離未來訓練資料，卻不能替缺少的 as-of 證據背書。
- **Recommended fix：** 建立公司級事件日期、財報可用日期、追蹤截止與 negative-label 成熟依據。取得前明確保留「回溯性事件重建」，另做更保守成熟延遲／尾端年度排除敏感度。不能因使用完整資料建標籤就直接斷言所有模型已洩漏；須證明哪些資訊在當時不可得、是否進入 fit／selection。

### R2：A/B 實作與正文描述不一致

- **Priority：P1。**
- **File／Function：** `study3_ab_fair_comparison.py::_run_a_and_baselines`；`experiments/phase4_drift/bankruptcy_drift_stream.py::load_bankruptcy_with_year`；`experiments/_shared/common_bankruptcy.py::_load_us_1999_2018`；論文 §3.1.1、§4.5。
- **Problem：** 公平比較的 A 是等權兩模型簡化版本。舊 loader 排除 `Division`，未排除 `MajorGroup`；去除年份後仍可含第 19 個數值特徵，與正文「兩路線均只使用 X1–X18」不符。
- **Why it matters：** 會讓讀者誤認 B 已與完整 A 在同一輸入下比較，甚至把舊 FS／權重效益轉嫁到 B。
- **Recommended fix：** 每個 Study 列 target、feature list、sampling、模型數、選擇規則、驗證契約、run ID。舊結果保留但標明實際輸入；若要正式比較完整 A，另以共同目標與特徵重跑。現有比較改稱「資料與評估協定對齊」，不要稱完全公平或等計算預算。

### R3：模型池消融同時改變歷史資料涵蓋，不能單獨證明集成機制

- **Priority：P1。**
- **File／Function：** `rolling_bankruptcy_overlap_ensemble.py::_run_year`；`scripts/analysis/analyze_study3b_pool_ablation.py::main`；論文 H₃₃、摘要與結論。
- **Problem：** 單模型窗口長 L、池大小 K 時，連續年度窗口聯集長 L+K−1。L=3 下，K=1／3／5 對應三／五／七年歷史。模型數、資料年代與重複曝光同時改變。
- **Why it matters：** Pool3 對 Pool1 的提升支持整體設計差異，不等於已辨識「模型保留本身」的因果貢獻。
- **Recommended fix：** 先充分使用已完成的 Recent5y 對照：B−Recent5y 的 AP 差 0.01649，95% CI [−0.00491, 0.03676] 跨零；AUC 差 0.02196，CI [0.00721, 0.03759] 未跨零。再補同五年資訊範圍、三模型預算的非時間分解集成，區分資料涵蓋、模型平均與年代專家效益。預先固定設計，不在現有 test 上搜尋最佳組合。

### R4：少數類目標缺少可接受的警報負擔定義

- **Priority：P1。**
- **File／Function：** `rolling_bankruptcy_overlap_ensemble.py::_evaluate`、`_operating_metrics`；論文 §4.5、§5。
- **Problem：** `Recall_at_5pctFPR` 容易被解讀為 test FPR 被固定在 5%；實際是 validation 選門檻。主要 F1 門檻仍漏掉 227／289 個正例。
- **Why it matters：** 「少數類辨識較好」必須同時回答多抓到多少、要審查多少公司、哪些年度失效。
- **Recommended fix：** 表頭寫明「validation-FPR≤5% 所選門檻下的 Test Recall」，旁列實現 FPR、Precision、TP／FP／FN、年度正例數。與教授固定主要 AP 及一個可解釋的警報預算；不必開始權重交叉驗證。評估 Precision@k／Recall@k 時須事前指定 k 與適用情境。

### R5：統計不確定性仍不足以支持普遍、穩定或最適主張

- **Priority：P1。**
- **File／Function：** `study3_ab_fair_comparison.py::paired_company_cluster_bootstrap`；sampling／pool／window 分析；論文 H₃₄ 與摘要。
- **Problem：** 公司群聚重抽保留公司內資料相依，但未重抽共同年度衝擊、未重新訓練，也未校正多方法、多指標比較。固定模型設定下十 seeds 一致，不代表對新年度或新資料穩定。
- **Why it matters：** 多次查看同一組 test 之後產生的新假設屬探索性；bootstrap 正差機率不是傳統 p 值。CI 跨零既不證明有效，也不證明等效或無效。
- **Recommended fix：** 區分主要比較與次要探索；並列逐年結果、年度中位數／範圍及預先指定的時間敏感度。十年資料下時間 block 推論本身也有限，不能承諾補一種 bootstrap 就解決。Tomek／Pool3／Window3 寫「尚未證明最優」；若要等效結論，需有等效界值與相應設計。

### R7：「永續」僅證明有界活躍模型數，未證明有界總成本

- **Priority：P1（若作核心效率主張）。**
- **File／Function：** `study3b_continual_runtime.py::update_state`、`_raw_snapshot_hash`、`_label_snapshot_hash`、`_load_training_data`。
- **Problem：** 每年只 fit 一個新模型成立，但仍完整讀取 raw／label 並雜湊歷史前綴；retired 模型、updates 與年度 registry snapshot 累積保存。活躍池大小固定不代表總儲存、讀取量、記憶體或 wall time 固定。
- **Why it matters：** 模型固定三個只能支持模型管理上的上界；無法直接推出可無限年運作且成本恆定。
- **Recommended fix：** 報 active-model bytes、archive bytes、讀取列數、峰值 RAM、fit 與 end-to-end update time。保留使用者要求的原始與結果資料，採 hot／archive 分層與增量索引，不擅自刪歷史；論文改成「固定活躍模型容量、每輪新增一模型」。

### R8：runtime 缺少更新協定指紋與逐列成熟完整性檢查

- **Priority：P1（持續更新正確性）；尚未證明污染現有回測。**
- **File／Function：** `study3b_continual_runtime.py::_load_training_data`、`_load_registry`、`update_state`。
- **Problem：** 成熟資料檢查主要確認必要年份出現，inner join 可能默默排除某年部分公司；配置／helper code 變動沒有完整 immutable protocol fingerprint 門檻，可能讓新模型與舊模型設定混合。
- **Why it matters：** 不完整年度資料可能造成 selection bias；流程可以成功更新，但已不是同一研究協定。
- **Recommended fix：** 明確定義預期 cohort 與允許延遲政策，逐列報未成熟／缺失／納入數，不把未到標籤当作負類；檢查二類存在。保存且驗證有效模型參數、前處理、features、標籤政策、依賴與來源版本；修改時建立新 protocol 或明示遷移。補「半年度標籤」「配置變動」「單一類別」「特徵全缺」測試。

### R9：消融彙整對多 seed 輸入的語義不安全

- **Priority：P2；若據此做多 seed 推論則升 P1。**
- **File／Function：** `scripts/analysis/analyze_study3b_{sampling,pool,window}_ablation.py::_load_seed_file/main`；`study3_ab_fair_comparison.py::paired_company_cluster_bootstrap`。
- **Problem：** seed 檔直接串接，配對鍵沒有 seed；部分 delta 取 baseline `.iloc[0]`。控制欄位也未完整驗證 seed／有效模型配置／環境相同。
- **Why it matters：** 目前單 seed 消融不因此失效；未來多 seed 卻可能把同一樣本重複當資料、錯配 seed 或產生不一致的比較基準。
- **Recommended fix：** 短期拒絕非單 seed 輸入；長期明確選擇「每 seed 獨立配對再摘要」或分層推論，驗證 method×seed×year×source key 唯一、seed 集一致及完整控制條件。十個相同 seeds 不當作十份獨立樣本。

### R10：FPR 門檻存在已重現的邊界 bug

- **Priority：P2；本輪未證明影響既有結果。**
- **File／Function：** `rolling_bankruptcy_overlap_ensemble.py::_select_threshold_at_fpr`。
- **Problem：** ROC 的全判負門檻 `inf` 被轉成 1.0，但決策採 `proba >= threshold`。本輪最小反例 `y=[0,1], p=[1.0,0.5], budget=.05` 回傳 1.0，validation FPR 反而為 100%。
- **Why it matters：** 極端機率時會違反函式宣稱的 validation 預算。另 `_select_f1_threshold` 只搜尋 .01–.99，不是所有可能決策的 F1 最適化；稀有事件可能需要更低門檻。
- **Recommended fix：** 保留明確全判負 sentinel／大於最大機率的門檻並處理序列化；回傳前重算 confusion matrix 驗證預算。F1 可改用 validation 的 distinct-score／PR 門檻，或明言 grid search。新增反例測試；若改門檻演算法，升 protocol 版本，不悄悄覆蓋舊結果。

- **Priority：P2（若作論文證據則 P1）。**
- **File／Function：** `scripts/analysis/validate_result_artifacts.py::audit_results/main`；`docs/研究方向.md` C6；run manifests；`requirements.txt`。
- **Problem：** audit 主要檢查 CSV 可讀與空檔；null／重複列是統計，不是完整語義判斷，也沒有證明跨檔無重複。window 分析有多個時間戳輸出，不能當多次獨立實驗。實驗 manifest 記錄 numpy 2.4.0，而 requirements 鎖 2.4.2，並非完全相同環境。
- **Why it matters：** 檔案可讀、可安裝、數值可重現是三個不同層次；重複分析輸出會造成結果來源混淆。
- **Recommended fix：** 指定每张正式表的唯一 run／analysis ID；不刪歷史。增加 schema、唯一鍵、時間邊界、預測重算與來源 hash 核對。保存執行環境完整 lock／有效預設參數，另以乾淨 venv 驗證 canonical requirements；不能只根據 Ubuntu CI matrix 宣稱所有作業系統已實测相容。

## Missing Experiments

### Must Have

1. **不新增訓練即可補的年度效益表。** 對所有主要方法補 yearly AP、正例數、TP／FP／FN、警報量、實現 FPR，與 pooled 指標並列；驗收：全部由逐筆預測重算且同 cohort。
2. **歷史資訊與模型預算對齊。** 先報現有 Recent5y 的差異區間，再補一個五年資料／三模型的非年代分解對照。驗收：清楚分開 unique rows、重複訓練曝光、模型數與更新成本。
3. **標籤成熟與尾端敏感度。** 用明確資料可用假設調整時距／追蹤截止，檢查主結論是否依赖樂觀時間假設；這不能取代真實 timestamp，只能量化敏感性。
4. **真實保存／恢复回歸與協定防護測試。** 小型真實 XGBoost fit-save-load-predict、部分標籤、變更配置、門檻極值；驗收：數值容差與拒絕條件事先指定。
5. **若保留完整 A／FS 為正式結論：** 在相同事件目標與隔離協定下重做必要的 A、FS 對照。若不做，將舊結果降為研究演進／探索附錄，而非混在 B 的效益證明中。

### Recommended

- 一個低複雜度基準（如正則化 logistic regression），以及一個適配年度延遲標籤的既有 stream ensemble。DWM 等已有專家新增／移除機制，不能把 FIFO 單獨當成首創；移植時註明 XGBoost 與 online learner 的差異與預算。[DWM 原論文](https://www.jmlr.org/papers/v8/kolter07a.html)。
- 年度／時間區塊敏感度與結果是否由少數年份驅動；只有十個 test 年份，誠實報低檢定力。
- 區分既有公司與新進公司的效果；同一公司跨年存在在既有公司預警任務中並非自動構成 leakage，但不能因此宣稱對全新公司泛化。
- 以年度資料量實測 update time、峰值 RAM、活躍與封存儲存量；多次 timing 與同硬體，不拿訓練模型數直接代替時間。
- 若以機率作風險排序以外的決策，再補 calibration／Brier 與漂移分布分析；目前不應直接把 XGBoost 輸出當校準破產機率。

### Optional

- 在 train／validation 內做 FS、有無取樣的有限交互作用分析；不先展開龐大 factorial 或權重搜尋。
- 真正新取得、尚未看過的年度或第二個同定義資料集作外部驗證。
- 若欲主張減少遺忘，另設固定歷史評估批次與跨更新效能矩陣。對凍結專家可量測整個 ensemble 的歷史效能變化，但不能套用「舊模型參數被覆寫」的解釋。

## Reviewer Perspective

### Strengths

- 問題聚焦在不平衡、年度批次與歷史模型保留，符合可解釋的企業風險研究情境。
- B 的訓練、validation、test 分工與版本化輸出較完整；逐筆預測可獨立重算。
- 已有正負消融結果；沒有必要為了論文而把 Tomek 或三年窗口寫成成功。
- 持久化模型與歷史回測的數值一致性，是可以展示的實作貢獻。

### Weaknesses / Major concerns

- 標籤是重建而非可驗證的當時事件資訊，限制前瞻適用性。
- 主方法是既有元件組合，尚未建立足夠的算法創新或機制辨識；更適合作為嚴謹的實證與系統流程貢獻。
- A、B、舊標籤、FS、漂移與權重故事混在正文，造成研究問題失焦。
- 少數類漏報與誤報成本未充分討論，年度不穩定被 pooled 分數遮蔽。
- 文獻錯配與 preregistered 用詞會削弱可信度，即使實验數字本身可重算。

Reviewer 最可能問：「你的 label 在當時真的存在嗎？改善是來自多看兩年資料還是集成？比較的是完整 DAWCE 嗎？如果 Tomek 和三年沒有優勢，核心貢獻究竟是什麼？只保留三個活躍模型就能稱永續嗎？」目前必須正面回答，而不是再增加圖表迴避。
