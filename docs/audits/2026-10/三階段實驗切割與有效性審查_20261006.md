## 問題與影響

1. **高（跨階段公平比較）：Phase 1 與最新 Phase 2／3 驗證協定不一致。** 當前 Phase 1 在各訓練年份內隨機抽約 20% 作 Validation，fit／validation 會包含相同年份；最新 Phase 2／3 固定保留整個 2014 年作獨立驗證。Phase 1 外層未混入 2015–2018 Test，不能因此就說 Phase 1 有直接 Test 洩漏；但其隨機年內驗證不是嚴格較晚年份驗證，資料可用範圍、前處理範圍與調參預算也不同。因此不得直接把不同協定的分數差解讀成純集成或 FS 效益。正式主比較需另以同一固定分區重跑 baseline；15 組年份邊界可保留為不同的敏感度實驗。
2. **高（前瞻主張）：破產 target 為公司最終狀態，並非已驗證的一年期事件。** 原始資料每家公司跨年 target 固定。Train、Test 可出現相同公司，這是追蹤既有公司的設定，不是未見公司泛化。年份互斥沒有解決事件日期／標籤成熟時間與財報發布時間的來源問題。結果可定位為回溯性分類與時間適應比較，不能直接當成未來一年破產預測已有效驗證。
3. **中：歷史 baseline CSV 缺少足夠來源對應。** 多個 XGBoost／RF／LR 根目錄結果仍含獨立 Finetune 分支；LightGBM、TabM、TabICL 另有三策略與部分完成的 run。新程式正確不能反推舊 CSV 已按新程式執行。每個正式表格須鎖定具體 run、方法集合、資料／程式版本與分區，再決定納入範圍。盤點詳見 JSON。
4. **中：TabM 的報表收尾仍有程式缺陷。** `_run_one_output_dir` 的 `args.splits`（`bankruptcy_year_splits_tabm.py:701`）引用 main 的區域變數，可能在已寫出 raw CSV 後中止報表流程。這不是年份遮罩錯誤，但「有 raw 檔」不代表整個入口已完整完成。本次僅記錄，未修改訓練程式。

前處理與特徵選取應只在允許的訓練資料擬合，Test 不參與選擇；這是本次查核的判準。[scikit-learn 資料洩漏指引](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)
